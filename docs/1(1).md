# 0. 先确定论文的候选主轴

我建议暂定主轴为：

> **Signal-Aware Online Post-Training for LLM-based Automatic Heuristic Design**

其中 “signal-aware” 包含两层：

# 1. 详细待验证假设清单

下面我按优先级给出。**P0 是决定论文是否成立的核心假设；P1 是支撑 AAAI 贡献强度的机制假设；P2 是增强/防守假设。**

## P0-H1：AHD-GRPO 存在 reward degeneracy

### 假设

在 AHD 中，frontier improvement 很稀疏。如果 reward 主要由“是否超过 parent / frontier / 是否 valid”这类离散状态构成，那么同一个 prompt 下多个 completions 很容易得到相同或近似相同的 reward，导致 GRPO 组内 advantage 退化。

形式化地，对同一 prompt 的 (K) 个 completions：

[
A_i=\frac{r_i-\bar r}{\operatorname{std}(r_1,\ldots,r_K)+\epsilon}
]

如果：

[
r_1=r_2=\cdots=r_K
]

则有效 advantage 近似为 0，GRPO 更新几乎没有区分信号。

如果 reward 近似只有 improvement / non-improvement 两类，improvement 概率为 (p)，则：

[
P(\text{zero-var}) = p^K + (1-p)^K
]

当 AHD 中 (p\ll 1) 时：

[
P(\text{zero-var}) \approx (1-p)^K
]

这说明稀疏 verifier reward 天然容易造成大量低效 GRPO update。

### 为什么重要

这直接支撑你的方向 2。
如果这个假设成立，你们的方法创新就不是“调 reward”，而是：

> **针对 AHD verifier reward 的 GRPO 信号退化问题，重构组内可区分训练信号。**

你们现有代码已经记录 parse failure、exec success、valid count、positive reward、parent/frontier improvement、zero-std、token usage/timing 等 summary 字段，适合验证这个假设。

### 需要验证的指标

| 指标                        | 目的                       |
| ------------------------- | ------------------------ |
| reward zero-std ratio     | 直接衡量 GRPO 是否退化           |
| group reward std          | 衡量组内信号强度                 |
| group score std           | 判断是否性能本身有差异但 reward 没捕捉到 |
| positive reward ratio     | 看 improvement 是否稀疏       |
| parent improvement rate   | 看局部改良频率                  |
| frontier improvement rate | 看全局突破频率                  |
| valid non-improving ratio | 看是否大量样本被压成同一负值           |

### 实验设计

至少比较：

1. sparse / CALM-style reward；
2. current four-state reward；
3. continuous relative performance reward；
4. continuous + group rank reward；
5. continuous + group rank + novelty reward。

### AAAI 判据

如果 proposed reward 能显著降低 `reward zero-std ratio`，同时提升 valid 条件下 parent/frontier improvement 或 best-so-far 曲线，就可以成为主方法贡献。

## P0-H2：AHD-RL 的提升可以分解为 valid rate、conditional improvement、improvement magnitude

### 假设

AHD-RL 的端到端提升不一定等价于“模型学会更强启发式设计”。它可能来自三个因素：

[
\mathbb{E}[\Delta^+]
====================

P(v=1)
\cdot
P(\Delta>0\mid v=1)
\cdot
\mathbb{E}[\Delta\mid v=1,\Delta>0]
]

其中：

* (P(v=1))：模型生成合法、可执行、非随机、非泄漏代码的概率；
* (P(\Delta>0\mid v=1))：在 valid 条件下，生成代码能改进 parent/frontier 的概率；
* (\mathbb{E}[\Delta\mid v=1,\Delta>0])：一旦改进，改进幅度有多大。

### 为什么重要

这是你想带上的“部分形态 1”。它可以防止论文变成单纯方法堆叠，并且帮助解释 CALM-like AHD-RL 的收益来源。

尤其是小模型场景中，RL 可能主要提升：

* code block 合法性；
* 函数签名匹配；
* 可执行率；
* 非随机性；
* 非复制率；
* 更少 runtime error。

而这些提升会提高有效搜索样本数，即使模型的 heuristic design capability 没有显著增强。

### 需要验证的指标

| 分解项                                   | 对应指标                                                           |
| ------------------------------------- | -------------------------------------------------------------- |
| (P(v=1))                              | parse success、signature success、exec success、finite score rate |
| (P(\Delta>0\mid v=1))                 | valid 条件下 parent/frontier improvement rate                     |
| (\mathbb{E}[\Delta\mid v=1,\Delta>0]) | valid improved samples 的平均提升幅度                                 |
| 搜索端收益                                 | best-so-far、valid eval efficiency、time-to-first-improvement    |

### 实验设计

1. EoH + base local model；
2. EoH + validity-only RL；
3. EoH + performance-only RL；
4. EoH + proposed group-discriminative reward；
5. SFT-only，如果已有 SFT pipeline；
6. SFT + proposed reward，作为 optional warm-start。

### AAAI 判据

如果 validity-only RL 能提升 valid rate 但不能明显提升 valid 条件下 improvement，那么你们可以提出：

> AHD-RL gains are confounded by validity learning; therefore, AHD post-training methods must report conditional heuristic improvement, not only final best score.

如果 proposed reward 同时提升 (P(v=1)) 和 (P(\Delta>0\mid v=1))，则方法贡献更强。

## P0-H3：Group-discriminative reward 比 sparse reward 更适合 AHD-GRPO

### 假设

AHD-GRPO 需要的不是更复杂的最终 score，而是更适合组内相对优化的 reward 结构。
一个有效 reward 应同时满足：

1. invalid 明确惩罚；
2. valid non-improving 不全部压成同一个值；
3. parent improvement 与 frontier improvement 区分；
4. 同组 valid samples 有可比较的 rank signal；
5. novelty 只作为弱辅助，不能主导性能。

### 候选方法

[
r_i
===

r_i^{perf}
+
\lambda_{rank}r_i^{rank}
+
\lambda_{nov}r_i^{nov}
]

其中：

[
r_i^{perf}=
\begin{cases}
1+\operatorname{clip}(\Delta_f/\tau_f,0,1), & \Delta_f>0\
b_p+\operatorname{clip}(\Delta_p/\tau_p,0,c_p), & \Delta_f\le 0,\Delta_p>0\
-\operatorname{clip}(-\Delta_p/\tau_w,l_w,u_w), & \Delta_p\le 0
\end{cases}
]

[
\Delta_f=s_i-s_{\text{frontier}},\quad
\Delta_p=s_i-s_{\text{parent}}
]

[
r_i^{rank} = \operatorname{rank_percentile}(s_i)-0.5
]

[
r_i^{nov} = \min_{j\in Parents} d_{\text{code}}(y_i,y_j)
]

约束：

[
\lambda_{rank}\ll 1,\quad \lambda_{nov}\ll \lambda_{rank}
]

并且：

[
r_i^{nov}=0
]

当 (y_i) invalid、random、leak、exact-copy 时。

你们当前 reward 已经有 continuous frontier / parent / valid-worse 结构，文档中也已经提出 rank 与 novelty 的增强方向。

### 需要验证的指标

| 指标                               | 预期               |
| -------------------------------- | ---------------- |
| reward zero-std ↓                | 组内训练信号更有效        |
| group reward std ↑               | 但不能过大到鼓励噪声       |
| parent improvement among valid ↑ | 局部改良增强           |
| frontier improvement ↑           | 全局突破增强           |
| invalid/random/copy 不上升          | novelty 没有诱导坏多样性 |
| best per valid eval ↑            | 样本效率提高           |

### AAAI 判据

如果 proposed reward 在多 seed 下稳定改善 zero-std 和 valid improvement，即使 final best 不是所有任务都赢，也可以支撑一个方法贡献。

---

## P0-H4：进化算子是 online post-training 的数据采样策略

### 假设

在 AHD-RL 中，operator 不只是搜索策略的一部分，也是后训练数据分布控制器。

定义：

[
o_t\sim q_t(o)
]

[
x_t=T(o_t,P_t)
]

[
y_{t,k}\sim \pi_{\theta_t}(\cdot\mid x_t)
]

其中 (o_t) 决定 prompt 类型、parent context、候选生成模式，进而决定 GRPO 训练样本分布。因此：

[
q_t(o)
]

本质上是 online post-training 的 data collection policy。

原始 EoH 使用固定算子流程；你们当前 EoH-RL 也仍然是固定 operator cycle。  当前文档也明确说明，自适应算子权重还没有真正启用。

### 需要验证的指标

按 operator 分组统计：

| 指标                                | 目的            |
| --------------------------------- | ------------- |
| valid rate by operator            | 哪些算子更容易生成合法代码 |
| parent improvement by operator    | 哪些算子更适合局部改良   |
| frontier improvement by operator  | 哪些算子更适合突破     |
| reward zero-std by operator       | 哪些算子训练信号更弱    |
| copy/random/leak rate by operator | 哪些算子容易产生坏样本   |
| operator utility over time        | 是否存在阶段依赖      |

### 实验设计

1. fixed EoH cycle；
2. uniform operator sampling；
3. CALM-like fixed prior；
4. evidence-aware adaptive operator；
5. hindsight oracle operator analysis，只作为上界分析。

### AAAI 判据

如果不同 operator 的 valid/improve/zero-std 差异明显，并且这些差异随阶段变化，那么 evidence-aware operator scheduling 就非常有动机。

## P0-H5：post-registration evidence 比 raw reward 更适合更新 operator credit

### 假设

raw reward 只能说明一个 completion 在当前 evaluator 上的即时分数；但对搜索来说，更重要的是它是否真正被注册、是否 surviving、是否成为后续 parent、是否被 duplicate/gate 阻断。

所以 operator credit 不应只来自 raw reward，而应来自 post-registration search evidence。

你们当前 EoH-RL 已经有 candidate registration 和事件回填机制，这正好能支持这个方向。

### 候选 operator credit

定义 operator (o) 在窗口内的事件：

* (F_o)：frontier improvement；
* (P_o)：parent improvement；
* (B_o)：blocked / invalid / duplicate / copy / random / leak；
* (V_o)：结构违规；
* (N_o)：样本数。

信号：

[
s_o
===

\frac{2F_o+P_o-B_o}{N_o+\epsilon}
\cdot
\left(1-\frac{V_o}{N_o+\epsilon}\right)
]

EMA 更新：

[
c_{o,t}
=======

(1-\alpha)c_{o,t-1}
+
\alpha s_{o,t}
]

采样分布：

[
q_{o,t}
\propto
q_o^{prior}\exp(c_{o,t}/\tau)
]

加入探索约束：

[
q_{\min}\le q_{o,t}\le q_{\max}
]

### 需要验证的指标

| 对比                                       | 目的                     |
| ---------------------------------------- | ---------------------- |
| raw-reward credit vs registration credit | 看 search evidence 是否更稳 |
| fixed operator vs adaptive operator      | 看样本效率                  |
| adaptive operator entropy                | 避免过早坍缩到单一算子            |
| per-operator credit trajectory           | 看是否符合搜索阶段变化            |
| invalid/copy 被压制情况                       | 看 credit 是否能避开坏算子      |

### AAAI 判据

如果 adaptive operator 不能显著提高 final best，但能显著提高 valid eval efficiency、降低 bad completion、降低 zero-std，也仍然有论文价值。

## P1-H6：reward 与 operator 之间存在交互，而不是两个独立模块

### 假设

更好的 reward 会改变每个 operator 的 apparent utility；更好的 operator sampling 又会改变 reward distribution。
因此 group-discriminative reward 和 evidence-aware operator 不是简单相加，而是相互耦合。

形式上：

[
\mu_o(t;r)=\mathbb{E}[\Delta^+\mid o_t=o,r]
]

operator 的效用依赖 reward definition。

### 需要验证

做 2×2 消融：

| Reward          | Operator |
| --------------- | -------- |
| sparse reward   | fixed    |
| proposed reward | fixed    |
| sparse reward   | adaptive |
| proposed reward | adaptive |

观察：

* proposed reward 是否让 operator credit 更稳定；
* adaptive operator 是否进一步降低 zero-std；
* 二者组合是否超过单独增益。

### AAAI 判据

如果组合收益明显大于单独模块，论文主方法就更强。
如果不是，也可以写成“reward 是主贡献，operator 是次要增强”。

## P1-H7：SFT 主要是 warm-start / anchor，而不是公平主对比优势

### 假设

SFT 在 AHD 中主要提升输出格式、任务模板、函数签名和基础 heuristic pattern，而不是直接提升 valid 条件下的 improvement rate。

你们当前 pipeline 中 SFT 位于 resident GRPO 之前。 但为了避免公平性问题，SFT 不应成为主方法默认配置，而应成为 optional warm-start。

### 需要验证的指标

| 指标                                | 目的          |
| --------------------------------- | ----------- |
| SFT-only valid rate               | 看是否主要提升合法性  |
| SFT-only conditional improvement  | 看是否真的提升设计能力 |
| SFT + GRPO vs no-SFT + GRPO       | 看二者是否互补     |
| SFT 数据量 / GPU 时间                  | 成本归一化       |
| cross-task / cross-scale transfer | 看 SFT 是否泛化  |

### 实验设计

1. no-SFT Fair-Core；
2. SFT-only；
3. SFT + proposed reward；
4. validity-SFT；
5. performance-SFT，如果有历史高质量数据。

### AAAI 判据

如果 SFT mainly improves validity，则它支持你的归因分析。
如果 SFT strongly improves final best，则需要严格报告数据与训练成本，并把它写成 enhanced setting。

## P1-H8：AHD-RL 存在 train/test 或 cross-scale generalization gap

### 假设

AHD-RL 可能优化训练实例上的 heuristic score，但不一定产生可泛化规则。
真正的 heuristic design improvement 应该在 held-out instances 或更大规模上保持有效。

### 需要验证的指标

| 指标                             | 目的          |
| ------------------------------ | ----------- |
| train best                     | 搜索优化目标      |
| validation best                | 选择稳定性       |
| test best                      | 泛化          |
| cross-scale score              | 规模迁移        |
| train-test ranking correlation | 训练得分是否能预测泛化 |

### 实验设计

* TSP50 search，TSP100/200 test；
* OBP small search，larger instances test；
* final discovered heuristic 在 held-out cases 上重评估。

### AAAI 判据

如果 proposed reward/operator 不仅提高训练 best，还提高 cross-scale generalization，这是很强结果。
如果没有，也至少要报告，避免被审稿人质疑 overfitting。

# 2. 可冲击 AAAI 的核心创新点

结合你偏好的 2+3+部分1，我建议把潜在创新点分成“主创新”和“可选增强”。

---

## 核心创新点 1：把 LLM4AHD 形式化为 verifier-based online post-training

这是框架外壳，来自形态 3。

### 核心表述

> LLM-based AHD with online RL is a verifier-based online post-training process in which the training distribution is generated by the interaction among the language policy, evolutionary operators, population state, and program evaluator.

形式化：

[
P_t: \text{population}
]

[
\theta_t: \text{LLM policy}
]

[
q_t(o): \text{operator distribution}
]

[
x_t=T(o_t,P_t),\quad o_t\sim q_t(o)
]

[
y_{t,k}\sim \pi_{\theta_t}(\cdot\mid x_t)
]

[
s_{t,k}=E(y_{t,k})
]

[
P_{t+1}=U(P_t,{y_{t,k},s_{t,k}})
]

[
\theta_{t+1}=G(\theta_t,{x_t,y_{t,k},r_{t,k}})
]

这说明 AHD-RL 不同于普通固定数据后训练，因为：

[
D_t = D(P_t,q_t,\theta_t,E)
]

训练数据分布随搜索状态、operator、模型参数共同变化。

### AAAI 价值

这个创新点本身不是算法，但能提升论文格局。
它说明你们不是“又一个 CALM-style RL”，而是在给 LLM4AHD 提供后训练视角下的统一问题定义。

---

## 核心创新点 2：Signal decomposition protocol

这是形态 1 的部分融入。

### 核心表述

> We decompose AHD-RL gains into validity learning, conditional heuristic improvement, and improvement magnitude.

公式：

[
\mathbb{E}[\Delta^+]
====================

P(v=1)
\cdot
P(\Delta>0\mid v=1)
\cdot
\mathbb{E}[\Delta\mid v=1,\Delta>0]
]

### 实验协议

所有 AHD-RL 方法都必须报告：

1. valid rate；
2. valid 条件下 parent improvement；
3. valid 条件下 frontier improvement；
4. improvement magnitude；
5. invalid/random/leak/copy；
6. final best；
7. valid eval efficiency。

### AAAI 价值

这可以作为一项“诊断贡献”。
它能回答：

> AHD-RL 到底是在提高模型生成合法代码的概率，还是在提高合法代码中的设计质量？

这个问题对 CALM-like 方法非常关键，也有较强普适性。

---

## 核心创新点 3：Group-discriminative reward for AHD-GRPO

这是最重要的方法创新。

### 问题

AHD verifier reward 不是没有，而是对 GRPO 来说经常过于稀疏、离散、低方差。

### 方法

[
r_i
===

r_i^{perf}
+
\lambda_{rank}r_i^{rank}
+
\lambda_{nov}r_i^{nov}
]

其中：

* (r_i^{perf})：连续 parent/frontier improvement；
* (r_i^{rank})：同 prompt 内 performance percentile；
* (r_i^{nov})：轻量结构新颖性；
* invalid / leak / random / copy 直接 gated；
* novelty 不能超过 performance 主项。

### 论文 claim

> Sparse verifier rewards induce degenerate GRPO groups in AHD. Our group-discriminative reward restores intra-group preference signals while preserving performance-driven optimization.

### 必须展示的结果

1. zero-std ratio 明显下降；
2. group reward std 更健康；
3. valid 条件下 parent/frontier improvement 上升；
4. bad completion 不上升；
5. best-so-far 或 sample efficiency 提升。

---

## 核心创新点 4：Evidence-aware operator scheduling

这是第二个方法创新。

### 问题

operator distribution 决定 online post-training 的 prompt distribution。固定 operator cycle 无法适应不同任务、阶段、模型状态。

### 方法

用 post-registration evidence 更新 operator credit：

[
s_o
===

\frac{2F_o+P_o-B_o}{N_o+\epsilon}
\cdot
\left(1-\frac{V_o}{N_o+\epsilon}\right)
]

[
c_{o,t}
=======

(1-\alpha)c_{o,t-1}
+
\alpha s_{o,t}
]

[
q_{o,t}
=======

\operatorname{ClipNormalize}
\left(
q_o^{prior}\exp(c_{o,t}/\tau)
\right)
]

### 论文 claim

> Evolutionary operators are not merely search heuristics; they are data collection policies for online post-training. We adapt them using post-registration evidence to allocate training queries toward operators with higher search utility.

### 必须展示的结果

1. 不同 operator 的收益确实不同；
2. adaptive operator 能改变 completion 分布；
3. 提高 valid eval efficiency；
4. 降低 bad operator 的使用；
5. 和 proposed reward 组合更强。

---

## 核心创新点 5：No-SFT fair core + optional SFT warm-start

这是公平性设计，不是主算法贡献。

### 核心表述

> To avoid conflating additional data with online post-training effects, we define a no-SFT Fair-Core setting. SFT is studied separately as an optional warm-start and anchor.

实验表述：

| Setting                           | 用途               |
| --------------------------------- | ---------------- |
| no-SFT + proposed reward/operator | 主公平对比            |
| SFT-only                          | 分析 SFT 学到什么      |
| SFT + proposed method             | enhanced variant |
| validity-SFT                      | 格式学习             |
| performance-SFT                   | 历史高性能数据学习        |

### AAAI 价值

这能防守审稿人对 SFT 数据开销和公平性的质疑。

---

## 核心创新点 6：Cost-normalized AHD post-training evaluation

这是形态 3 的实证框架贡献。

### 核心表述

> AHD-RL comparisons should be normalized not only by final score, but also by LLM completions, valid evaluations, training GPU time, and optional SFT data cost.

报告：

[
\text{BestPerValidEval}
=======================

\frac{\text{BestScoreImprovement}}{#\text{valid evals}}
]

[
\text{BestPerGPUHour}
=====================

\frac{\text{BestScoreImprovement}}{\text{GRPO GPU hours}+\text{SFT GPU hours}}
]

以及：

* total completions；
* valid completions；
* invalid completions；
* train time；
* inference tokens；
* valid-eval efficiency。

### AAAI 价值

如果你们 final best 不总是碾压 CALM/strong online baseline，这个评价协议可以让论文仍然站得住。

# 3. 最推荐的最终贡献组合

我建议最终论文不要超过 4 个主贡献。可以写成：

### Contribution 1：Post-training formulation and signal decomposition

我们将 LLM-based AHD online RL 形式化为 verifier-based online post-training，并提出 validity / conditional improvement / improvement magnitude 的收益分解。

### Contribution 2：Group-discriminative AHD-GRPO reward

我们指出 sparse verifier reward 会导致 GRPO reward degeneracy，并提出 continuous performance + group rank + lightweight novelty 的 reward。

### Contribution 3：Evidence-aware operator scheduling

我们把 EoH operators 视为 post-training data collection policy，并用 post-registration search evidence 自适应调度。

### Contribution 4：Controlled evaluation under fair and cost-normalized settings

我们在 no-SFT fair core 下对比 CALM-style / EoH baselines，并把 SFT 作为 optional warm-start 单独分析。

这个组合正好是：

* 形态 2 的方法核心；
* 形态 3 的框架与评价；
* 形态 1 的部分归因。

# 6. 最终论文可能的标题与摘要骨架

## 标题候选

**Signal-Aware Online Post-Training for LLM-based Automatic Heuristic Design**

或者：

**SAGE-AHD: Group-Discriminative GRPO and Evidence-Aware Search Control for Automatic Heuristic Design**

## 摘要骨架

> Recent methods apply online reinforcement learning to LLM-based automatic heuristic design, using evaluated heuristic programs as feedback for post-training. However, unlike standard RLHF/RLVR, AHD post-training is coupled with evolutionary search: rewards are sparse and often degenerate within GRPO groups, generated programs mix code validity learning with genuine heuristic improvement, and evolutionary operators determine the on-policy training distribution.
> We propose SAGE-AHD, a signal-aware online post-training framework for LLM-based AHD. SAGE-AHD decomposes AHD-RL gains into validity, conditional improvement, and improvement magnitude; introduces group-discriminative rewards combining continuous performance improvement, within-group ranking, and lightweight novelty; and adapts evolutionary operators using post-registration search evidence. Experiments under no-SFT fair-core and optional SFT warm-start settings show that SAGE-AHD reduces reward degeneracy, improves valid search efficiency, and discovers stronger heuristics under matched evaluation and training budgets.

# 7. 最关键的取舍

你现在偏向 2+3 融合，这很好。但需要明确主次：

**主方法：**

1. group-discriminative reward；
2. evidence-aware operator scheduling。

**主框架：**

3. AHD as verifier-based online post-training。

**主分析：**

4. validity vs heuristic improvement decomposition。

**降级为防守/增强：**

5. SFT warm-start；
6. LoRA drift；
7. collapse；
8. 强在线模型成本分析。

一句话概括最终方向：

> **用后训练视角重新定义 AHD-RL，用 group-discriminative reward 解决训练信号退化，用 evidence-aware operator scheduling 控制在线训练数据分布，再用 signal decomposition 证明提升来源不是单纯格式合法性。**
