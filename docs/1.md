你的问题如果是 **AAAI 2027 冲刺**，我建议不要把主线写成“CALM 可能有 performative feedback 问题”。这太窄，也容易被反驳：CALM 的实验证据确实显示有效。更有价值的论文切口应该是：

> **LLM-based AHD 后训练收益的机制归因问题：RL 到底提升了算法设计能力，还是主要提升了可执行性、格式对齐、搜索可消费性和搜索轨迹记忆？**

这可以把你的假设扩展成一套更强的 research agenda。

---

## 1. CALM 原文里最值得抓住的几个信号

CALM 的核心主张是：已有 LLM-based AHD 主要依赖 prompt 层面的 verbal guidance，而 CALM 额外引入 performance-based RL fine-tuning，即所谓 numerical guidance，使 LLM 与算法搜索过程共同演化。原文明确说，启发式不断被生成、评估和筛选，形成 prompt-response-performance triplets，然后用这些信号通过 RL 微调 LLM，使模型“internalize characteristics of successful heuristics”。([arXiv][1])

但这里有一个关键张力：CALM 的奖励函数并不是纯粹“算法质量奖励”。它首先对不可行输出分层惩罚，包括缺少 idea、缺少 code block、函数格式错误、runtime error/time budget violation、随机模块等；并且原文明确说，**任何 feasible heuristic 都比 infeasible response 奖励更高**，以确保 basic correctness 被优先学习。([arXiv][1]) 这直接支持你的怀疑：RL 信号中很大一部分可能在训练模型“生成可被框架解析和执行的代码”，而不是训练真正的启发式设计能力。

CALM 的消融实验也留下了归因空间。Table 4 中，local w/ GRPO 在 OBP 上 gap 为 0.71%，local w/o GRPO 为 1.78%，说明 GRPO 对小模型确实有明显帮助；但 CALM API w/o GRPO 也达到 0.82%，已经接近 local w/ GRPO。原文同时承认，即使不使用 RL，CALM 的 verbal guidance 版本已经能达到或超过部分强 baseline。([arXiv][1]) 这意味着：**CALM 的效果可能来自三者混合：prompt operator 设计、搜索框架设计、RL 后训练，而不是 RL 单独解释。**

因此，你的论文不要简单说“CALM 的 RL 无效”。更稳的说法是：

> CALM 证明了在线 RL fine-tuning 在 AHD 中有效，但没有充分解释这种有效性来自哪里。现有评估主要报告 final best score，缺少对 validity、conditional quality、diversity、novelty、generalization、credit assignment 的机制拆解。

## 2. 你的原始假设可以升级成两个主假设

### 假设 A：闭环在线训练存在耦合偏置，但短期内可能被鲁棒性掩盖

CALM 的训练数据来自当前搜索过程，训练后的模型又继续参与后续搜索。这个系统可以写成：

[
\theta_t \rightarrow D_t \rightarrow \theta_{t+1} \rightarrow D_{t+1}
]

其中 (D_t) 不是独立同分布数据，而是由当前模型、当前 prompt operator、当前 evaluator、当前种群共同诱导的：

[
D_t \sim p(x,r \mid \theta_t, E_t, \mathcal{P}*t, \mathcal{I}*{train})
]

这会带来几个潜在问题：

[
\text{search-induced bias}, \quad
\text{evaluator overfitting}, \quad
\text{mode collapse}, \quad
\text{distribution narrowing}
]

但你判断“影响可能较小”是合理的，因为 CALM 训练轮次有限，模型更新受 KL/GRPO 约束，演化搜索本身有 collapse 和 diversity-aware crossover 机制，基础模型也有较强先验。CALM 原文本身也承认搜索会出现 inbreeding 和 premature convergence，并设计了 collapse mechanism 来重置种群、保留 seed 与 best heuristic。([arXiv][1])

所以论文里可以写成：

> The feedback loop is structurally biased, but its negative effect may not manifest in short-horizon benchmarks. The important question is not whether CALM fails, but when co-evolution improves, saturates, or degenerates.

这个表述更适合 AAAI。

### 假设 B：小模型收益主要来自 validity/format alignment，而非 algorithmic design ability

这是你最有价值的假设。CALM 使用 INT4 量化的 Qwen2.5-7B-Instruct，只微调 1.15% 权重，并强调它能超过更强 API 模型。([arXiv][1]) 但对于小模型来说，AHD 最大瓶颈往往不是“想不出好算法”，而是：

[
p(\text{parsable}) ,\quad
p(\text{compilable}),\quad
p(\text{runtime-safe}),\quad
p(\text{interface-correct})
]

如果 RL 主要提升这些概率，那么固定 query budget 下，有效评估数会上升：

[
N_{\text{valid}} = N_{\text{query}} \cdot \rho_{\text{valid}}
]

最终 best-of-(N) 性能自然提高：

[
\mathbb{E}[\max s] \uparrow
]

即使条件质量分布不变：

[
p_{\theta_{\text{RL}}}(s \mid \text{valid})
\approx
p_{\theta_{\text{base}}}(s \mid \text{valid})
]

这会形成一种“看起来像算法设计能力提升”的现象。

## 3. 可以进一步提出的更多假设

下面这些假设可以组成 AAAI 论文的 hypothesis bank。建议优先选 4–6 个做扎实实验，而不是全做。

---

### H1：Validity Funnel Hypothesis

CALM 的 RL 首先学习的是从 invalid 到 valid 的漏斗，而不是从 mediocre heuristic 到 strong heuristic 的迁移。

形式化：

[
\Delta_{\text{RL}}
==================

\Delta_{\text{validity}}
+
\Delta_{\text{quality}\mid\text{valid}}
+
\Delta_{\text{diversity}}
]

你的怀疑是：

[
\Delta_{\text{validity}} \gg \Delta_{\text{quality}\mid\text{valid}}
]

实验设计：

1. 记录每轮输出的 failure type：missing idea、missing code block、wrong function、runtime error、timeout、randomness、valid。
2. 比较 base model、RL model、validity-only RL model。
3. 对齐 valid candidate 数量后比较 final best score。

最关键的判断：

[
\text{若 valid-count matched 后 RL 优势消失，则收益主要来自 validity。}
]

---

### H2：Search Consumability Hypothesis

RL 提升的不是代码合法性本身，而是“候选能否被进化搜索消费”。

这比 H1 更细。AHD 里一个候选不仅要能跑，还要能作为 parent 被后续 prompt 使用。例如它需要：

[
\text{clear idea},\quad
\text{modular component},\quad
\text{short code},\quad
\text{named mechanism},\quad
\text{editable structure}
]

CALM 的 injection、replacement、simplification 都依赖模型生成可被后续操作引用的 component description。原文的 injection operator 要求模型加入新组件，并写出 concise description；replacement operator 则要求重写已有组件。([arXiv][1])

因此，小模型 RL 可能学到的是：

[
p(\text{evolution-friendly heuristic}) \uparrow
]

而不是：

[
p(\text{algorithmically superior heuristic}) \uparrow
]

实验指标：

* component 可抽取率；
* prompt 中 parent idea 的复用率；
* 下一代候选相对 parent 的可编辑性；
* heuristic description 与 code 的一致性；
* 被选为 parent 后的 offspring success rate。

这很适合做成新指标：**Evolutionary Consumability Score, ECS**。

---

### H3：Credit Misattribution Hypothesis

CALM 的 reward 是 response-level reward，但启发式性能由多个因素共同决定：

[
r = f(\text{prompt}, \text{parent heuristic}, \text{operator}, \text{LLM output}, \text{evaluator noise})
]

GRPO 给 response token 分配同一个归一化 advantage。CALM 原文也意识到这个问题，所以设计 fine-granularity mutation operators，希望让结构变化更可控，从而帮助 GRPO 识别单个结构变化的贡献。([arXiv][1])

但这也暴露了一个研究缺口：reward 仍然很可能错误归因。例如一个高分 offspring 可能只是因为 parent 本来很强，而不是 response 的改动有效。

可提出假设：

[
\text{CALM's RL partially learns parent-conditioned imitation rather than causal improvement.}
]

实验设计：

1. 将同一个 response modification 应用于不同 parent，测其边际贡献。
2. 对同一 parent 采样多个 response，估计 operator-level variance。
3. 构造 counterfactual reward：

[
\Delta r = r(h_{\text{child}}) - r(h_{\text{parent}})
]

4. 比较 absolute reward、parent-relative reward、causal marginal reward。

AAAI 价值点在于：你不是质疑 RL，而是提出 **causal credit assignment for LLM-based AHD**。

---

### H4：Operator Imitation Hypothesis

CALM 的训练数据并不是任意 algorithm design 数据，而是由 CALM 的 operators 诱导出来的：

[
D_t = D(\text{injection}, \text{replacement}, \text{crossover}, \text{simplification})
]

因此 RL 后的模型可能主要学会了 CALM operators 的输出风格。例如更会：

* 加一个 component；
* 改写一个 component；
* 合并两个 idea；
* 简化冗余代码；
* 输出符合模板的 explanation。

这不等于算法设计能力提升，而是：

[
p_{\theta}(\text{CALM-style response}) \uparrow
]

实验：

1. 用 RL 后模型脱离 CALM operators，直接做 zero-shot heuristic generation。
2. 用 RL 后模型接入 EoH/ReEvo/MCTS-AHD 框架，观察是否迁移。
3. 用非 CALM operator 生成 prompt，测试模型是否仍然提升。

判断标准：

[
\text{若只在 CALM prompt 下提升，说明主要是 operator-specific adaptation。}
]

---

### H5：Parametric Search Memory Hypothesis

在线 fine-tuning 后，LLM 参数可能扮演的是“搜索记忆”的角色，而不是学到通用算法能力。

传统演化搜索中，记忆存在于 population/archive。CALM 则额外把搜索轨迹压进参数：

[
\mathcal{M}_t = (\mathcal{P}_t, \theta_t)
]

因此 RL 后模型可能只是记住了当前任务中哪些结构、词汇、代码片段、公式形式更容易被 evaluator 奖励。

实验：

1. 训练后清空 population，仅保留 (\theta_t)，重新搜索。
2. 保留 population，但重置 (\theta_t)。
3. 同时保留/清空二者做 2×2 对照。

四组：

[
(\theta_0, P_t),\quad
(\theta_t, P_0),\quad
(\theta_t, P_t),\quad
(\theta_0, P_0)
]

如果 ((\theta_t, P_0)) 仍然强，说明参数确实存储了可迁移搜索经验；如果不强，说明主要收益仍在 population/search trajectory。

---

### H6：Conditional Quality Hypothesis

真正的 algorithmic design ability 应该体现在：

[
p(s \mid \text{valid}) \quad \text{improves}
]

而不是 final best score improve。

实验应比较完整分布，而不是只看 best：

* valid rate；
* mean score among valid candidates；
* median score；
* top-10% score；
* best-of-k curve；
* diversity-conditioned best-of-k；
* novelty-conditioned quality。

最重要的是 best-of-k 曲线：

[
B(k)=\mathbb{E}[\max_{i \leq k} s_i \mid h_i \in \mathcal{H}_{valid}]
]

如果 RL 的 (B(k)) 在相同 (k) 下显著更高，才说明算法质量分布真的改善。

---

### H7：Diversity Collapse Masking Hypothesis

CALM 有 diversity-aware crossover 和 collapse mechanism。原文说 collapse 用于应对 inbreeding 和 premature convergence；消融表也显示去掉 collapse 后性能下降。([arXiv][1])

但这可能掩盖另一个现象：

> RL 本身可能降低多样性，而 collapse/diversity-aware crossover 在外部补救这种退化。

也就是说：

[
\text{RL} \Rightarrow \text{mode concentration}
]

[
\text{collapse + diversity operator} \Rightarrow \text{restore exploration}
]

如果只看最终性能，会误以为 RL 本身提升了搜索；但实际上是 RL 加速 exploitation，collapse 负责重启 exploration。

实验：

1. 记录每轮 code embedding diversity、AST diversity、behavioral diversity。
2. 比较 w/ RL 与 w/o RL 的多样性曲线。
3. 关闭 collapse 后观察 RL 是否更快陷入 stagnation。
4. 用 fixed diversity injection 控制探索强度。

这个假设很有潜力，因为它能解释“RL 有效但有潜在闭环风险”。

---

### H8：Simplification as Regularization Hypothesis

CALM 消融中，去掉 simplification 在 OBP 和 OP 上都有明显退化，原文解释为 simplification 能减少冗余、抑制复杂度增长。([arXiv][1])

这可以扩展成一个更强假设：

> AHD 中的高性能提升不一定来自更复杂的启发式，而可能来自对 LLM 过度组件堆叠倾向的结构正则化。

LLM 生成启发式常见问题是“component accumulation”：

[
h_{t+1}=h_t + c_1 + c_2 + \cdots
]

性能短期可能提高，但泛化性和稳定性下降。

实验：

* 代码长度 vs train/test gap；
* component 数量 vs OOD gap；
* simplification 前后性能变化；
* 删除冗余项后的性能变化；
* AST complexity vs generalization。

可以提出指标：

[
\text{Heuristic Complexity Gap} =
s_{train}(h) - s_{test}(h)
]

看复杂度越高是否越容易 overfit。

---

### H9：Evaluator Overfitting Hypothesis

CALM 在固定训练实例上评估启发式，然后用这些评估结果训练模型。这个过程天然可能产生 evaluator overfitting：

[
h^* = \arg\max_h \text{Eval}_{train}(h)
]

但真实目标是：

[
\mathbb{E}*{I \sim \mathcal{D}*{test}}[s(h,I)]
]

RAISE 近期工作明确指出，现有 LLM-based AHD 方法在固定训练实例集上优化，遇到真实 distribution shift 时可能严重退化，并在 OBP、OJSP、OVRP 上报告 existing methods under distribution shift can degrade by up to 19×。([arXiv][2])

所以你可以把 CALM 纳入更大问题：

> Online RL fine-tuning may amplify evaluator overfitting because it not only selects heuristics using the evaluator, but also updates the generator toward evaluator-favored regions.

实验：

1. train instance 数量从小到大；
2. train distribution 与 test distribution 可控偏移；
3. 比较 w/ RL 是否比 w/o RL 更容易过拟合；
4. 用 adversarial validation instances 作为 reward regularizer。

这是 AAAI 很强的方向，因为它关联 robustness/generalization，而不是只做归因分析。

---

### H10：Reward Scale Sensitivity Hypothesis

CALM 的 feasible reward 比较 child 与 best parent，并对 improvement 给正奖励，对 underperformance 给负奖励。原文也测试了 performance-based reward 和 improvement reward，结果原设计更好。([arXiv][1])

但这个结果可能说明 reward design 很脆弱。假设：

[
\text{AHD-RL performance is highly sensitive to reward shaping, not robustly driven by algorithmic signal.}
]

实验：

* 改变 infeasible penalty scale；
* 改变 feasible/infeasible reward gap；
* 改变 trivial reproduction reward；
* 改变 improvement threshold；
* 加入 novelty bonus；
* 加入 complexity penalty；
* 加入 OOD validation reward。

如果最终性能对 reward shaping 极敏感，说明“训练信号足够让模型学习算法设计能力”的说法需要弱化。

---

### H11：Small-Model Alignment Bottleneck Hypothesis

小模型和大模型的收益机制可能不同。

对小模型：

[
\Delta \approx \Delta_{\text{format}} + \Delta_{\text{validity}}
]

对大模型：

[
\Delta \approx \Delta_{\text{strategy}} + \Delta_{\text{search prior}}
]

CALM 主要使用 7B INT4 本地模型，并与 GPT-4o-mini API baseline 比较。([arXiv][1]) 这给你一个很好的切口：**后训练收益是否随模型规模变化而机制不同？**

实验：

* 1.5B / 3B / 7B / 14B / API model；
* 每个模型做 same-budget RL；
* 分别测 validity gain、conditional quality gain、diversity change。

预期：

[
\text{smaller model: validity gain dominates}
]

[
\text{larger model: conditional quality gain may dominate or RL gain shrinks}
]

这个假设非常适合 AAAI，因为它能解释为什么小模型 RL 看起来很强。

---

### H12：Best-Score Illusion Hypothesis

AHD 论文通常报告 best heuristic 的最终 performance。但 best score 是一个极端统计量，容易被有效样本数、方差、搜索多样性影响。

即使两个模型的平均质量一样，只要一个模型产生更多 valid samples 或更高 variance，就可能有更好的 best score：

[
\mathbb{E}[\max X_i]
]

随样本数和方差增长。

因此，CALM 的 final best score 提升可能来自：

[
\text{more valid samples}
+
\text{higher variance}
+
\text{stronger exploitation}
]

而不一定来自整体质量分布改善。

实验：

* 固定 valid count；
* 固定 diversity；
* 固定 candidate variance；
* 报告 full distribution；
* 用 bootstrap 估计 best-of-k 置信区间。

论文贡献可以是：提出 **AHD Mechanistic Evaluation Protocol**。

## 4. 我认为最适合 AAAI 2027 的主线

你现在最有希望的主线不是做一个“比 CALM 更强”的方法，而是做：

> **Disentangling Post-Training Gains in LLM-Based Automatic Heuristic Design**

核心问题：

> When RL improves LLM-based AHD, what exactly is improved?

可以把贡献设计成三部分。

### Contribution 1：机制分解框架

将 AHD-RL 收益拆成：

[
\Delta_{\text{AHD}}
===================

\Delta_{\text{validity}}
+
\Delta_{\text{search-consumability}}
+
\Delta_{\text{conditional-quality}}
+
\Delta_{\text{diversity}}
+
\Delta_{\text{generalization}}
]

这比现有“最终 gap”评估更细。

### Contribution 2：反事实评估协议

提出几组关键对照：

1. valid-count matched evaluation；
2. validity-only RL baseline；
3. repair-augmented base model；
4. population/model memory 2×2 ablation；
5. cross-operator transfer；
6. OOD distribution shift evaluation；
7. best-of-k conditional quality curve。

这些实验不需要你发明特别复杂的新算法，但论文会很扎实。

### Contribution 3：一个更稳的训练/搜索改进方法

在机制发现后，可以提出一个方法，例如：

**Decoupled Validity-Quality Training for AHD**

先训练 validity，再训练 quality，避免二者混在一起：

[
r = r_{\text{valid}} + \lambda r_{\text{quality}} + \mu r_{\text{novelty}} - \gamma r_{\text{complexity}}
]

或者：

**Validity-Controlled Evolutionary RL**

在 GRPO 更新时，对 valid 和 invalid 分开归一化，避免 validity signal 淹没 algorithmic signal。

再或者：

**Causal Parent-Relative Reward**

将 child 的 reward 写成真正的边际贡献：

[
r(h_c \mid h_p)
===============

## s(h_c)-s(h_p)

## \alpha \cdot \text{similarity}(h_c,h_p)

\beta \cdot \text{complexity}(h_c)
]

这样你的论文不只是分析 CALM，而是提出一个更合理的训练范式。

## 5. 最建议优先验证的 5 个假设

按 AAAI 性价比排序，我建议优先做：

1. **Validity Funnel Hypothesis**
   这是你的核心直觉，最容易打出强证据。

2. **Conditional Quality Hypothesis**
   这是判断“是否真的提升算法设计能力”的关键。

3. **Parametric Search Memory Hypothesis**
   这很新：LLM 参数到底是在学习，还是在缓存搜索轨迹。

4. **Diversity Collapse Masking Hypothesis**
   这能连接你的 performative feedback 怀疑和 CALM 的 collapse mechanism。

5. **Evaluator Overfitting Hypothesis**
   这能把论文提升到 robustness/generalization 层面，AAAI 更容易认可。

## 7. 最终建议

你的判断非常适合发展成 AAAI 2027 论文，但需要避免“批判 CALM”这个姿态。更好的定位是：

> CALM/EvoTune opened the door to post-training LLMs during heuristic search, but current evidence does not explain why post-training helps. We provide the first mechanistic study and controlled evaluation protocol for post-training gains in LLM-based AHD, showing that much of the improvement, especially for small models, may come from validity and search-consumability rather than genuine conditional heuristic-quality improvement.

这条线很稳，因为即使实验发现 RL 确实提升了 conditional quality，你的论文仍然成立：你提出了机制分解、评估协议和更细粒度结论。
如果实验发现主要是 validity gain，那就是非常强的结果。
