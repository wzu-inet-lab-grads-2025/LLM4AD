# CALM强化学习与代码合法率对比分析报告

## 1. 研究目的

本报告分析 CALM 在开启强化学习（GRPO）与关闭强化学习（no-GRPO）两种设置下，生成代码的合法率差异。目标是回答以下问题：

1. 开启强化学习后，CALM 生成代码的合法率是否提高。
2. 这种提升是否稳定存在于整个搜索过程中，而非仅体现在最终结果。
3. 合法率差异主要来自哪些失败类型的变化。
4. 在相同合法输出数量下，强化学习是否也能带来更优的最优算法性能。
5. 当前日志是否足以支持“强化学习有效提升代码合法率”的结论。

本报告基于以下 6 组日志目录：

1. `calm_saved/obp/local_1kc100_grpo_3`
2. `calm_saved/obp/local_1kc100_grpo_4`
3. `calm_saved/obp/local_1kc100_grpo_5`
4. `calm_saved/obp/local_1kc100_no_grpo_0`
5. `calm_saved/obp/local_1kc100_no_grpo_1`
6. `calm_saved/obp/local_1kc100_no_grpo_2`

使用的主要文件包括：

1. `legality_summary.jsonl`
2. `response_audit.jsonl`
3. `trace.json`
4. `output.log`

其中，`legality_summary.jsonl` 是最核心的数据来源，因为它逐步记录了每一步的：

1. 输出总数 `total_model_outputs_seen`
2. 合法输出数 `legal_outputs`
3. 合法率 `legal_rate`
4. 可执行率 `executable_rate`
5. 唯一合法率 `unique_valid_rate`
6. 拒绝类型计数 `rejection_counts`
7. 接受类型计数 `acceptance_counts`

## 3. 核心结论

先给出结论，再展开分析。

1. 开启强化学习后，CALM 的代码合法率明显高于关闭强化学习。
2. 这种优势不是偶然出现在最终时刻，而是在中早期就已出现，并且能持续保持。
3. 强化学习不仅提高了合法率，也显著提高了可执行率。
4. 强化学习的主要收益表现为减少了基础结构性失败，例如 `idea_not_exist`、`function_not_exist` 和大规模 `duplicate_code`。
5. 在相同合法输出数量条件下，GRPO 能更快达到该合法量，但同合法量下的最优性能并非稳定更优。
6. 在最终最优性能上，GRPO 出现了一定提升迹象，但三次运行中仍有一次与 no-GRPO 持平。
7. no-GRPO 三个目录的结果完全一致，说明它们不能被视为三个真正独立的随机重复实验。

## 4. 指标解释

### 4.1 合法率定义

本报告中的“代码合法率”直接采用日志中的 `legal_rate`。

定义为：

```text
legal_rate = legal_outputs / total_model_outputs_seen
```

其中：

1. `legal_outputs` 表示被系统接受为合法新算法的输出数量。
2. `total_model_outputs_seen` 表示模型总共生成了多少个候选输出。

从日志看，在这些运行中：

1. `legal_rate`
2. `unique_valid_rate`

二者数值相同，因此可以将其理解为：

“模型生成输出中，最终被认为是合法、有效且非重复新算法的比例”。

### 4.2 可执行率定义

日志中的 `executable_rate` 表示输出是否至少进入了可运行、可评估层面。

这比 `legal_rate` 更宽松。

因此：

1. `legal_rate` 反映最终合法产出质量。
2. `executable_rate` 反映输出能否跨过最基础的语法、结构、运行门槛。

## 7. 中间过程动态分析

如果只看最终结果，可能会担心提升只是偶然出现在后期。因此需要比较整个搜索过程。

### 7.1 按共同输出预算对比合法率

为了尽量公平，这里不直接按 step 比，而是按共同累计输出数量比较。

| 累计输出数 | GRPO 平均合法率 | no-GRPO 平均合法率 | 绝对差值 | 倍数 |
| ---: | ---: | ---: | ---: | ---: |
| 500 | 0.144667 | 0.094000 | 0.050667 | 1.5390 |
| 1000 | 0.131000 | 0.073000 | 0.058000 | 1.7950 |
| 1500 | 0.120889 | 0.072667 | 0.048222 | 1.6637 |
| 2000 | 0.116667 | 0.060000 | 0.056667 | 1.9444 |

### 7.2 过程性结论

这张表揭示了几个重要现象：

1. 在 500 个输出时，GRPO 已明显高于 no-GRPO。
2. 这种优势在 1000、1500、2000 输出时持续存在。
3. no-GRPO 的合法率随着过程推进持续下滑。
4. GRPO 的合法率也有所下降，但下降幅度更小，且始终维持在更高水平。

### 7.3 no-GRPO 的衰减趋势

no-GRPO 组在若干关键 step 的合法率如下：

1. step 10: 0.200000
2. step 50: 0.140000
3. step 100: 0.105000
4. step 200: 0.076250
5. step 300: 0.075833
6. step 400: 0.070000
7. step 500: 0.060000

这说明 no-GRPO 在前期还能维持一定合法率，但随着搜索继续，生成越来越倾向于产生重复、无效或结构失败的候选，导致合法率不断下降。

### 7.4 GRPO 的稳定性

GRPO 在相同输出预算下的平均合法率大致保持在：

1. 500 outputs: 0.144667
2. 1000 outputs: 0.131000
3. 1500 outputs: 0.120889
4. 2000 outputs: 0.116667

这说明强化学习并没有随着搜索深入而迅速“失效”，而是能够长期维持较好的结构约束与生成质量。

### 8.2 no-GRPO 组最终失败占比

| 类型 | 平均占比 |
| --- | ---: |
| `duplicate_performance_profile` | 0.398000 |
| `duplicate_code` | 0.299000 |
| `idea_not_exist` | 0.129500 |
| `function_not_exist` | 0.094500 |

| `code_bug` | 0.005000 |
| `random_algorithm` | 0.005000 |
| `code_not_exist` | 0.001000 |

### 8.3 重点解释

#### 8.3.1 `idea_not_exist` 大幅下降

no-GRPO：0.1295  
GRPO：0.0552

这说明关闭强化学习时，模型更容易连合格的算法想法描述都给不出来。强化学习显著减少了这种最基础的生成失败。

#### 8.3.2 `function_not_exist` 明显下降

no-GRPO：0.0945  
GRPO：0.0513

说明强化学习帮助模型更好地遵循函数模板要求，生成更完整、可解析的代码结构。

#### 8.3.3 `duplicate_code` 显著下降

no-GRPO：0.2990  
GRPO：0.1442

关闭强化学习时，大量输出是完全重复或实质重复实现。GRPO 能显著缓解这种模式坍缩现象。

#### 8.3.4 `duplicate_performance_profile` 反而更高

no-GRPO：0.3980  
GRPO：0.5723

这个现象不能简单解释为“GRPO 更差”。

更合理的解释是：

1. no-GRPO 的很多候选在更早阶段就因为结构问题被淘汰。
2. GRPO 让更多候选至少进入“可执行、可评估”的后端阶段。
3. 因此，更多 GRPO 输出是在性能层面被判定为重复，而不是在结构层面提前死亡。

这实际上说明 GRPO 把大量候选从“前端非法区”推进到了“后端可评估区”。

## 11. 同合法输出数量下的最优性能分析

前面的分析主要关注合法率，即“生成多少比例的代码是合法的”。

但从科研角度，还需要进一步追问一个更细的问题：

> 在达到相同合法输出数量时，开启强化学习是否也能得到更优的最优算法性能？

这里采用共同合法输出数量：

```text
legal_outputs = 120
```

选择这个值的原因是：

1. 三个 no-GRPO 运行最终都恰好达到 120 个合法输出。
2. 三个 GRPO 运行都能达到或超过 120 个合法输出。
3. 因此该值适合作为两组共同可比的合法量基线。

### 11.1 到达 120 个合法输出时的最优性能

| 运行目录 | 达到 120 合法输出时的 step | 当时总输出数 | 当时最优性能 `best_perf` | 当时可执行率 |
| --- | ---: | ---: | ---: | ---: |
| `local_1kc100_grpo_3` | 258 | 1032 | -2.119701 | 0.682171 |
| `local_1kc100_grpo_4` | 201 | 804 | -2.119701 | 0.691542 |
| `local_1kc100_grpo_5` | 240 | 960 | -1.995012 | 0.696875 |
| `local_1kc100_no_grpo_0` | 497 | 1988 | -2.119701 | 0.464789 |
| `local_1kc100_no_grpo_1` | 497 | 1988 | -2.119701 | 0.464789 |
| `local_1kc100_no_grpo_2` | 497 | 1988 | -2.119701 | 0.464789 |

### 11.2 直接结论

这一结果揭示两点：

1. **GRPO 更快达到同样的合法输出数量**
   - GRPO 大约在 `804` 到 `1032` 个总输出时就达到 120 个合法输出。
   - no-GRPO 需要接近 `1988` 个总输出才达到 120 个合法输出。
   - 说明 GRPO 的样本效率更高，能更快地把模型输出推进到“合法候选积累”的阶段。

2. **同合法量下的最优性能并没有稳定优势**
   - `grpo_3`：达到 120 合法输出时 `best_perf = -2.119701`，与 no-GRPO 持平。
   - `grpo_4`：达到 120 合法输出时 `best_perf = -2.119701`，与 no-GRPO 持平。
   - `grpo_5`：达到 120 合法输出时 `best_perf = -1.995012`，略优于 no-GRPO。
   - 也就是说，只有在一次运行中，GRPO 在同合法量下的最优性能更好，其余两次与 no-GRPO 持平。

因此：

1. **GRPO 的主要优势不是更早找到更优性能，而是更快、更稳定地积累合法输出。**
2. **在“同合法量下的最优性能”上，GRPO 没有表现出稳定一致的提升。**

### 11.3 如果看最终最优性能

如果不按共同合法量，而是看各运行结束时的最终 `best_perf`：

1. `grpo_3`: `-2.119701`
2. `grpo_4`: `-1.995012`
3. `grpo_5`: `-1.745636`
4. `no_grpo_0/1/2`: `-2.119701`

这说明：

1. 有两次 GRPO 运行在最终最优性能上优于 no-GRPO。
2. 一次 GRPO 运行与 no-GRPO 持平。
3. 因此 GRPO 在最终最优性能上出现了一定提升迹象，但并非稳定一致地超越。

### 11.4 这部分结论在科研表述上的意义

基于当前日志，可以更严谨地写成：

1. GRPO 显著提升了合法率。
2. GRPO 显著提升了合法输出积累速度。
3. GRPO 显著提升了可执行率。
4. 但在“相同合法输出数量”条件下，GRPO 没有展现出稳定更优的最优性能。
5. 在最终最优性能上，GRPO 出现了一定提升迹象，但并非每次都优于 no-GRPO。

因此，当前证据更适合支持下面的命题：

> 强化学习主要改善了 CALM 的结构合法性与合法候选获取效率，并在部分运行中带来最终最优性能的提升，但尚不足以声称 GRPO 稳定提升了同合法量下的最优算法性能。

## 12. 实验设计的公平性与局限性

### 12.1 实验口径已严格对齐

本报告所使用的 3 组 GRPO 日志（`grpo_3/4/5`）与 3 组 no-GRPO 日志（`no_grpo_0/1/2`）在以下条件上完全一致：

1. `max_steps = 500`
2. `n_prompts = 1`
3. `n_generations = 4`
4. `seed = 1926000`
5. 同一模型
6. 同一数据集
7. 同一温度与 `top_p`
8. 同一搜索参数
9. 同一推理/加载路径
10. 主循环均由 `max_steps` 控制，不被 `evaluation_budget` 提前截断

两组之间的唯一显式差异为 `enable_grpo` 开关。

因此，本报告的对比属于严格意义上的“唯一变量”对照实验。

### 12.2 no-GRPO 三个 run 完全一致

三个 no-GRPO 目录的 `legality_summary.jsonl` 哈希完全相同。

这意味着：

1. `local_1kc100_no_grpo_0`
2. `local_1kc100_no_grpo_1`
3. `local_1kc100_no_grpo_2`

三者不是“非常接近”，而是**逐字节一致**。

因此，这三次不能被当作真正独立的随机重复实验。可能原因包括：

1. 固定随机种子导致 no-GRPO 路径完全确定。
2. 三个目录来源于同一结果的复制。
3. no-GRPO 路径在当前代码下本身就是确定性执行。

无论原因是哪一种，这都意味着：

1. no-GRPO 组没有提供真正意义上的 run-to-run 方差估计。
2. 本报告对 no-GRPO 的统计只能做描述性分析，不能做严格的随机重复显著性检验。

## 13. 学术结论写法建议

如果要把这批日志写入论文或技术报告，可以使用如下学术化表述：

> 在 OBP 任务上，CALM 在引入 GRPO 后，其生成代码的合法率与可执行率均明显提升。基于 3 组 GRPO 运行日志与 3 组 no-GRPO 运行日志的分析，两组均在固定 500 代、每代 4 个主输出、同一模型、同一随机种子的严格同构条件下运行。GRPO 组最终合法率均值为 11.67%，而 no-GRPO 组为 6.00%，前者约为后者的 1.94 倍；可执行率均值分别为 69.47% 与 46.30%。在共同输出预算下，GRPO 在 500、1000、1500 与 2000 个累计输出节点上始终保持更高的合法率，表明其优势贯穿整个搜索过程。失败类型分解显示，GRPO 的主要收益来自减少 idea 缺失、函数缺失与重复代码等前端结构性失败，并使更多候选进入可执行但性能重复的后端筛选阶段。此外，GRPO 在明显更少的总输出数下即可达到与 no-GRPO 相同的合法输出量，显示出更高的合法候选获取效率。但在“相同合法输出数量”条件下，GRPO 的最优算法性能并未稳定优于 no-GRPO；在最终最优性能上，GRPO 也在三次运行中有两次优于 no-GRPO、一次持平。综合来看，强化学习主要改善了 CALM 的结构合法性与合法候选获取效率，并在部分运行中带来最终最优性能的提升，但尚不足以声称 GRPO 稳定提升了同合法量下的最优算法性能。

## 14. 最终结论

基于当前 6 组日志，可以给出以下最终判断：

1. 开启强化学习后，CALM 生成代码的合法率显著提高。
2. 该提升是稳定的、过程性的，而非仅体现在最终结果。
3. 强化学习的主要作用是减少基础结构错误，并提高输出的可执行性与结构完整性。
4. 在当前日志下，GRPO 对合法率的提升幅度约为 no-GRPO 的 1.94 倍。
5. GRPO 在同合法量下并未稳定展现出更优的最优性能，但在最终最优性能上出现了一定提升迹象。
6. 当前实验口径已在 `max_steps`、`n_generations`、`seed`、模型、数据、搜索参数等维度严格对齐，唯一显式差异为是否开启 GRPO。
7. 唯一仍需注意的方法学局限是：no-GRPO 三次运行完全一致，缺少独立重复方差，因此对该组的统计只能做描述性分析。
