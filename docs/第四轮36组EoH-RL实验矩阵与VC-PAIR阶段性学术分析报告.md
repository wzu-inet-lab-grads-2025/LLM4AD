# 第四轮 36 组 EoH-RL 实验矩阵与 VC-PAIR 阶段性学术分析报告

## 摘要

本报告对 `logs/TSP/eoh_local_rl/tsp50_vc_pair_500_6seed/20260715_vc_pair_500_6seed_run01` 中完成的 36 组实验进行系统复核。实验由 6 个方法变体、6 个随机种子、每次 500 轮进化更新构成；每个 prompt 采样 4 个 response，共产生 18,000 个在线 prompt 组、72,000 个在线候选 completion。全部实验使用同一 TSP50 任务、同一 SFT LoRA、同一组 64 个训练实例，并在相同 seed 内共享冻结的初始种群，因而适合进行 seed 内配对比较。

本轮的核心结果如下。

1. 36/36 次运行均完成到第 500 轮，不存在“初始化后提前退出”、缺轮、断点混入或不完整 run 被纳入统计的问题。
2. 以最终 archive best score 为主要指标，`vc_pair_lr0` 均值最高，为 `-6.242959`；相对不训练的 `b0_fixed` 的配对差为 `+0.021996`，但 95% 置信区间为 `[-0.020158, +0.064151]`，尚不能拒绝零效应。
3. 当前项目的 `aggregate_reset` 与 `b0_fixed` 几乎持平，配对差为 `+0.001855`，95% CI `[-0.064610, +0.068320]`；不能证明 aggregate 奖励带来收益。
4. `validity_reset` 相对 B0 为 `-0.003996`；`shuffled_reset` 为 `-0.044094`；当前临时 `vc_pair_reset` 为 `-0.024314`。其中 shuffled 的负效应方向最稳定，但在仅 6 个 seed 下双侧配对 t 检验仍为 `p=0.074818`。
5. 有效候选供给显著增加并没有转化为更高最终质量。`shuffled_reset` 的 eligible rate 最高，为 90.642%，但最终成绩最差；这直接支持 PDF 中“必须区分 validity mediation 与 conditional quality”的诊断思想，也否定“只要合法率提高，搜索性能就会自然提高”的简化假设。
6. 当前 `vc_pair_reset` 不是 PDF 所定义的最终 VC-PAIR。日志中的实现以 `mean ± 1 SE` 和固定 margin 分类，而 PDF 要求基于同批实例的直接父子配对差、置信区间或胜率、最小效果阈值、分层合法性门控、可靠正向 frontier 奖励和退化惩罚。因此本轮只能评价“临时 VC 奖励实现”，不能据此否定最终 VC-PAIR 机制。
7. 临时 VC 奖励的正样本极度稀疏：10,165 个 eligible 候选中仅 31 个被标为 positive，占 0.305%；4,143 个为 neutral，5,991 个为 negative。训练后期模型主要把 negative 转成 neutral，同时 duplicate rate 从第一个 100 轮窗口的 3.79% 上升到最后窗口的 32.50%，parent-win rate 从 1.85% 降至 0.10%。这更像学会规避明显失败和趋近父代，而不是学会产生稳定改进。
8. LoRA 参数确实发生了更新，GRPO 指标、reward std、KL、梯度范数和 adapter norm 均有真实记录；不存在“开启训练但实际未更新”的虚假训练。`vc_pair_lr0` 的 adapter norm 严格不变，也符合零学习率对照的预期。
9. 本轮仍不足以支撑论文级最终结论：只覆盖 TSP50、只覆盖 SFT 初始化、没有无 SFT 主线、没有 OBP/JSSP 和跨规模验证、没有 fixed prompt/parent bank 的 search-free tail、没有 within-prompt reward shuffle、没有 same-valid-budget 曲线、没有 QueriesToKValid/AUC、没有峰值显存和能耗。因此本报告将其定位为 PDF 主实验之前的机制诊断矩阵，而不是最终方法验证。

在本报告中，TSP evaluator 返回负路径长度，因此**分数越大越好，即越接近 0 越好**。所有“差值”均定义为“目标方法减去对照方法”；正值表示目标方法更好。

1. 全部变体都从 SFT LoRA 出发，无法回答 PDF 主线中的“无 SFT 时 RL 是否独立有效”。

## 3. 统计分析方案

### 3.1 主要统计单位

最终搜索性能的主要统计单位是独立 run/seed，而不是 72,000 个候选。对于方法 $m$ 与 B0，在每个 seed $s$ 上计算：

\[
d_s = y_{m,s}^{(500)} - y_{B0,s}^{(500)}.
\]

报告以下指标：

- 6 个配对差的均值；
- 配对差样本标准差；
- 自由度 5 的 Student-t 95% 置信区间；
- 双侧单样本配对 t 检验；
- exact Wilcoxon signed-rank 作为小样本稳健性补充；
- 胜出 seed 数；
- 配对标准化效应量 $d_z=\bar d/s_d$。

候选级、轮级和算子级统计均为**描述性机制证据**。由于同一 run 中候选共享模型、prompt、父代、实例和历史 archive，不能把它们作为 72,000 个独立样本进行显著性检验。

### 3.2 多重比较与统计功效

本轮有多个变体比较，但没有预注册主假设，也没有执行多重比较校正。因此所有 p 值仅用于阶段性筛选，不用于宣称确认性发现。每个变体仅 6 个 seed，置信区间较宽；“未显著”不等于“证明无效”，但也不能把均值方向当作已证实收益。

### 3.3 漏斗定义

用以下事件描述从文本到可用于搜索的程序：

- $C$：格式/解析成功；
- $X$：代码执行成功；
- $A$：候选满足 eligible 条件；
- $N$：相对 archive 新颖；
- $W$：在同批评估中优于直接父代；
- $F$：进入 frontier。

关键条件概率为：

\[
P(C),\quad P(X\mid C),\quad P(A\mid X),\quad P(N\mid A),\quad P(W\mid A).
\]

这比只报告最终合法率更能区分“模型学会输出可执行程序”和“模型学会输出更优程序”。

## 4. 六个变体的真实语义

### 4.1 B0：关闭 GRPO

`b0_fixed` 是本轮进化搜索基线。它仍然使用加载后的 SFT LoRA 生成候选，但不执行 GRPO 参数更新。它回答的是：在相同模型初始化和进化预算下，不做在线 RL 后训练时能达到什么结果。

### 4.2 LR0：零学习率流水线对照

`vc_pair_lr0` 建立与 VC 分支相近的 Trainer/奖励流水线，但学习率为 0。其 adapter norm 全程保持 `52.999493`，证明参数没有发生数值更新。它用于识别以下非学习因素：

- Trainer 初始化和重建；
- 训练分支的数据整理；
- 采样/缓存/RNG 路径差异；
- 每轮进入 reward 与 trainer 生命周期带来的系统差异。

LR0 不是“另一个有效学习方法”，而是必要的工程对照。

### 4.3 Aggregate：本项目的 aggregate 奖励

`aggregate_reset` 使用本项目现有的父代相对、frontier/aggregate 组合奖励，并在每轮重建 Trainer。它只能被称为本项目 aggregate 奖励消融。没有证据表明其数学定义与 CALM 完全相同，因此不能称为“CALM 奖励”或“CALM 复现”。

### 4.4 Validity：合法性导向奖励

`validity_reset` 主要奖励格式正确、可执行和 eligible。它用于估计 RL 是否能提高有效程序供给，以及单纯提高有效性是否足以提高最终搜索质量。

### 4.5 Shuffled：当前 shuffled 对照

`shuffled_reset` 破坏 reward 与候选质量之间的对应，用于检测训练收益究竟来自有效的质量排序信号，还是来自一般的格式/分布正则化。但当前实现不等价于 PDF 更严格要求的“同 prompt、仅在 valid 候选中置乱质量 reward”；所以其阴性结果是有价值的负对照证据，却不能完全替代最终 shuffle 实验。

### 4.6 VC：当前临时 VC 实现

当前运行配置为：

| 参数 | 本轮值 |
|---|---:|
| `pair_se_multiplier` | 1.0 |
| `pair_margin` | 0.0001 |
| positive reward | 1.0 |
| neutral reward | 0.0 |
| negative reward | -0.5 |

其判定依赖父子均值差和 1 个标准误，而不是最终方案要求的 95% 置信区间。当前还缺少或未严格实现：

- `group_valid_count >= 2` 时才启用组内质量偏好；
- 基于同一批实例的严格直接父子 paired difference；
- 真实 95% CI 或等价的可信胜率；
- 可靠正向 frontier bonus；
- duplicate-profile penalty；
- PDF 规定的完整分层非法类别与质量门控组合。

当前已有 exact-parent-copy penalty，但不能覆盖上述缺口。因此后文将其写作“临时 VC”，不将其结果外推到最终 VC-PAIR。

LR0 相对 B0 的均值为正但不显著，且所有非零学习率变体均未优于 LR0。尤其 Shuffled 在 6/6 seed 上都差于 LR0，其区间不跨零。该结果说明正式实验必须同时保留 B0 与 LR0：只和 B0 比较会把训练效果与流水线路径差异混在一起。

### 7.2 “代码合法率”的三层统一口径

“代码合法率”不能只用一个 parse 指标表示。本报告以全部 12,000 个在线 completion 为统一分母，同时报告格式合法、执行合法和搜索可用三个层级：

| 变体 | 格式合法率 Parse/Total | 执行合法率 Exec/Total | 搜索可用率 Eligible/Total | 新颖可用率 Novel/Total |
|---|---:|---:|---:|---:|
| B0 | 94.500% | 86.467% | 77.742% | 75.850% |
| LR0 | 94.808% | 85.933% | 77.883% | 76.100% |
| Aggregate | **98.308%** | **94.567%** | 89.683% | 70.442% |
| Validity | 97.908% | 90.625% | 83.733% | 79.067% |
| Shuffled | 98.217% | 92.967% | **90.642%** | **86.025%** |
| 临时 VC | 98.225% | 93.392% | 84.708% | 69.542% |

其中：

- 格式合法率表示 response 能被 parser 识别为满足函数合同的代码；
- 执行合法率要求程序实际运行成功并产生有限结果；
- 搜索可用率进一步排除随机算法、评估元数据泄漏和直接父代复制；
- 新颖可用率还要求候选不与 archive 中已有程序重复。

因此，如果必须选择一个最接近“真实代码合法率”的主口径，应使用 `Eligible/Total`，同时把 Parse 与 Exec 作为失败归因指标。按该口径，B0 为 77.742%，Aggregate 为 89.683%，Validity 为 83.733%，Shuffled 为 90.642%，临时 VC 为 84.708%。但 Shuffled 合法率最高而最终成绩最差，进一步说明合法率不能替代质量指标。

|---|---:|---:|---:|---:|---:|---:|---:|
| B0 | 94.500% | 91.499% | 89.909% | 97.567% | 98.231% | 0.868% | 0.622% |
| LR0 | 94.808% | 90.639% | 90.632% | 97.710% | 98.277% | 1.027% | 0.717% |
| Aggregate | **98.308%** | **96.194%** | 94.836% | **78.545%** | **81.472%** | 1.115% | 0.706% |
| Validity | 97.908% | 92.561% | 92.395% | 94.427% | 95.989% | 0.826% | 0.537% |
| Shuffled | 98.217% | 94.655% | **97.499%** | 94.907% | 96.139% | 0.506% | 0.349% |
| 临时 VC | 98.225% | 95.079% | 90.702% | 82.095% | 86.355% | 0.600% | 0.443% |

### 7.4 validity mediation 的核心发现

学习变体普遍提高了格式/解析成功率。Aggregate 和 Shuffled 的解析成功率超过 98%，明显高于 B0 的 94.5%。Shuffled 还把 `P(A|X)` 提升到 97.499%，最终获得 10,877 个 eligible 候选，比 B0 多 1,548 个。

但增加的有效候选并不等价于增加高质量候选：

- Shuffled 的 eligible 数全组最高，parent-win 仅 55，frontier 仅 38，最终分数全组最差。
- Aggregate 的 parent-win/frontier 总数最高，但 archive-novel 比例降至 78.545%，其最终分数仍与 B0 持平。
- 临时 VC 的解析和执行表现较好，但 novel/eligible 仅 82.095%，并没有形成正向质量收益。

因此，本轮最可靠的机制结论是：

\[
\text{RL} \rightarrow \text{更多格式正确/可执行候选}
\]

在若干变体中成立；但

\[
\text{更多有效候选} \not\Rightarrow \text{更高最终搜索质量}.
\]

这正是 PDF 要求把 validity、conditional quality 和 search outcome 分开检验的原因。

## 8. 重复、父代改进与退化趋势

### 8.1 汇总比例

| 变体 | Eligible rate | Novel/全部 | Duplicate/eligible | Parent-win/eligible | Frontier/eligible | `{{idea}}` 出现率 | Zero reward-std 组率 |
|---|---:|---:|---:|---:|---:|---:|---:|
| B0 | 77.742% | 75.850% | 2.483% | 0.870% | 0.624% | 2.958% | 27.333% |
| LR0 | 77.883% | 76.100% | 2.270% | 1.031% | 0.719% | 3.058% | 30.000% |
| Aggregate | 89.683% | 70.442% | **21.253%** | **1.114%** | 0.708% | 2.267% | **6.333%** |
| Validity | 83.733% | 79.067% | 5.608% | 0.828% | 0.537% | 0.683% | **51.067%** |
| Shuffled | **90.642%** | **86.025%** | 5.111% | 0.505% | 0.349% | 0.367% | 13.000% |
| 临时 VC | 84.708% | 69.542% | 17.933% | 0.600% | 0.442% | 0.558% | 23.067% |

### 8.2 解释

Aggregate 和临时 VC 的主要风险不是“无法产生合法代码”，而是合法代码逐渐集中到重复或近父代区域。Aggregate 的 duplicate/eligible 为 21.253%，临时 VC 为 17.933%，分别是 B0 的约 8.6 倍和 7.2 倍。

Validity 的 zero reward-std 组率达到 51.067%。GRPO 依赖组内相对优势；当 4 个 response 获得相同 reward 时，该 prompt 组几乎不提供可区分的策略梯度。合法性奖励能把模型推向可执行区域，但一旦 4 个 response 都合法，其学习信号就会迅速饱和。

Shuffled 的 reward std 不算最低，却由于质量对应关系被破坏而获得最差结果。这说明“存在梯度”与“梯度方向有用”是两个不同问题。

## 9. 临时 VC-PAIR 奖励信号审计

### 9.1 组内有效候选数

临时 VC 共 3,000 个 prompt 组，每组 4 个 response。组内 eligible 数分布为：

| Eligible 个数 | 组数 | 占比 |
|---:|---:|---:|
| 0 | 9 | 0.300% |
| 1 | 83 | 2.767% |
| 2 | 318 | 10.600% |
| 3 | 914 | 30.467% |
| 4 | 1,676 | 55.867% |

因此 `group_valid_count >= 2` 在本轮 SFT-TSP50 设置下满足 2,908/3,000 组，即 96.933%。如果补上该 gate，它只会直接屏蔽 3.067% 的组，不能单独解释临时 VC 的负结果。但这个 gate 在无 SFT、跨问题或大规模任务中可能重要得多，不能因为 TSP50 上触发少就删除。

### 9.2 正、中性、负奖励分布

| 变体 | Eligible 候选 | Positive | Neutral | Negative | Positive/eligible |
|---|---:|---:|---:|---:|---:|
| B0 的事后 VC 分类 | 9,329 | 37 | 969 | 8,323 | 0.397% |
| LR0 的事后 VC 分类 | 9,346 | 38 | 733 | 8,575 | 0.407% |
| 临时 VC 训练 | 10,165 | 31 | 4,143 | 5,991 | **0.305%** |

临时 VC 中：

- 只有 31 个 positive，占全部 12,000 completion 的 0.258%；
- 只有 28/3,000 个组至少包含一个 positive，占 0.933%；
- 4,143 个 neutral，占 eligible 的 40.757%；
- 5,991 个 negative，占 eligible 的 58.938%。

在 500 轮、每轮 4 response 的预算下，平均每约 96.8 轮才产生一个 positive 候选（按每 run 总体平均），正向监督极为稀疏。GRPO 大部分时间只能学习“不要明显变差”，而不是“怎样可靠改进”。

### 9.3 配对统计分布

临时 VC 日志中的父子配对统计为：

| 指标 | 均值 | 中位数 |
|---|---:|---:|
| paired mean difference（全部） | -4.2224 | -0.2160 |
| positive 候选 paired mean | +0.1400 | +0.0712 |
| negative 候选 paired mean | -7.1631 | -1.3083 |
| paired SE | 0.0760 | 0.0458 |
| instance-level win rate | 0.0766 | 0.0000 |

均值和中位数差异巨大，说明负差分布存在明显长尾。若直接使用原始平均差作为连续 reward，少量灾难性候选可能主导尺度；分桶、置信区间和稳健聚合是必要的，而不是形式上的复杂化。

### 9.4 用 95% t 区间进行事后重分类

本轮配置使用 `1 × SE`。若利用日志中的 (n=64) 个实例和记录的 mean/SE，事后改用自由度 63 的双侧 95% t 临界值，并保持 `margin=1e-4`，分类会变为：

| 数据来源 | 当前 Negative | 当前 Neutral | 当前 Positive | 95% t Negative | 95% t Neutral | 95% t Positive |
|---|---:|---:|---:|---:|---:|---:|
| B0 | 8,323 | 969 | 37 | 7,918 | 1,391 | 20 |
| LR0 | 8,575 | 733 | 38 | 8,332 | 999 | 15 |
| 临时 VC | 5,991 | 4,143 | 31 | 5,665 | 4,487 | **13** |

这表明严格 95% CI 会把临时 VC 的可靠正样本从 31 个进一步降到 13 个，仅占 eligible 的 0.128%。所以最终 VC-PAIR 不能只把 `SE multiplier` 从 1 改为约 2 就结束；必须同时设计正向信号密度、frontier bonus、最小效果阈值、分层有效性和可能的多轮/批次证据聚合，否则训练信号会过于稀疏。

### 12.3 本轮真实 prompt 的逐项审计

从 `history.tar.gz/online_grpo/update_001/prompts.json` 等实际运行产物读取的 prompt，而不是仅阅读当前源代码，可以确认本轮 prompt 包含：

- 问题自然语言描述与优化方向；
- 一个或两个父代的截断 idea 描述；
- 父代完整函数代码；
- `e1/e2/m1/m2` 对应的交叉或变异语义；
- “以最强父代为性能锚点”“引入结构上不同的决策成分”等改进要求；
- 确定性、禁止随机数/时间/外部状态/隐藏评估信息；
- 精确的函数模板、函数名、参数和返回类型；
- “恰好输出 idea 与一个 Python 函数”的格式要求；
- 简洁实现、避免冗余全量重计算的约束。

Prompt record 另外保存 `parent_best_score`、64 维 `parent_best_profile`、`parent_best_id`、`parent_codes`、`parent_ids`、`population_best_score`、operator 和 `reward_contract`。这些字段用于 reward 与审计；实际送入模型的数据集只包含 `messages`，数值 score/profile 不在用户 prompt 文本中。这个分离设计可以降低模型直接抄写评估元数据的风险。

| PDF/实验要求 | 本轮真实状态 | 判定 |
|---|---|---|
| 提供直接父代代码 | 已提供，并保存 parent id | 已对齐 |
| 明确 operator 语义 | e1/e2/m1/m2 均有不同自然语言要求 | 已对齐 |
| 明确 deterministic/interface 约束 | prompt 中明确，parser 也检查 | 已对齐 |
| 强调相对父代的实质改进 | 有 performance anchor 与 meaningful difference 表述 | 基本对齐 |
| 防止 score leakage | score/profile 仅作隐藏 metadata；另有 leakage detector | 基本对齐 |
| 强制 idea + code 契约 | prompt 要求，但 parser 允许 idea 缺失 | 未闭环 |
| Idea 进入 reward/去重/算子 credit | 当前 reward 不消费 idea | 未对齐 |
| 固定 prompt/parent bank | 在线父代随 archive 变化 | 本轮未覆盖 |
| 同 prompt 的跨方法严格复用 | 同 seed 初始状态匹配，但后续 prompt 分叉 | 未覆盖 |
| 跨规模显式条件 | 使用通用 task/template，未显式编码 scale/难度 | 框架通用但证据不足 |
| Repair/template 提示基线 | 未运行 | 未覆盖 |

这里最关键的区别是：**本轮 prompt 文本本身已经比早期 EoH 的宽松输出要求更严格，但训练闭环仍主要按“代码是否可解析/执行及其分数”工作。** Idea 是模型被要求生成的解释性文本，却不是 eligibility 的必要条件，也不是 reward 输入。因而低 idea compliance 不会阻止程序进入 population，训练自然缺少提高该字段合规率的直接压力。

此外，在线 prompt 随 archive 和父代选择不断变化。不同变体在早期生成一次不同候选后，后续父代、代码和 prompt 便会分叉。这是有效的真实搜索评估，却不能替代 PDF 要求的 fixed bank：后者用于回答“给定完全相同父代与 prompt，后训练模型的输出分布是否更好”。正式论文需要同时保留在线搜索和固定 bank 两种协议。

关于 `{{idea}}` 是否“对强化学习真的有影响”，本轮能得出的严谨回答是：**当前它几乎没有形成稳定的训练契约，因此不能用本轮结果判断 idea 字段本身是否有益**。如果最终方法需要 idea 作为可解释轨迹、去重特征或 operator credit 的输入，就必须把其格式合法率单独记录并在 prompt/parser 中强制；如果奖励和搜索完全不消费 idea，则不应声称它已经参与强化学习。

## 18. 对核心研究问题的回答

### RQ1：在线 GRPO 是否提高了最终搜索性能？

在本轮 TSP50 上，没有证据支持。Aggregate、Validity 和临时 VC 相对 B0 的配对置信区间均跨零；相对 LR0 也没有优势。不能据此断言所有正确设计的 GRPO 都无效，只能说明当前奖励实现尚未形成可复现的终点收益。

### RQ2：GRPO 是否提高有效程序生成？

是，描述性证据很强。多个训练变体将 parse rate 从 B0 的 94.5% 提高到约 98%，并提高 exec/eligible 供给。该结果说明模型确实学习了输出分布约束。

### RQ3：有效性提升是否中介了搜索收益？

有效性提升存在，但搜索收益没有同步出现。Shuffled 是最清晰的反例：eligible 最高、最终结果最差。因此当前证据支持“validity 是必要但不充分条件”，不支持“合法率就是主要最终指标”。

### RQ4：当前质量奖励是否教会模型产生更优程序？

尚无支持。Parent-win/frontier 极稀疏，并随轮次下降；临时 VC 主要把 negative 变成 neutral，同时产生明显复制/低新颖性退化。Aggregate 的 parent-win 总数略高，但终点与 B0 持平，且重复率严重上升。

### RQ5：当前 VC 结果能否否定 PDF 的 VC-PAIR？

不能。当前实现不满足 PDF 最终统计定义，并且缺少关键的正向 bonus、分层 gate 和 duplicate-profile penalty。本轮只证明 `mean ± 1SE`、固定三值 reward 的临时版本在当前预算下没有优于基线。

### RQ6：SFT 是否掩盖了 RL 的主要作用空间？

这是高度合理但尚未被本轮直接检验的解释。所有变体初始都加载 TSP-small SFT LoRA；即使 B0 的 parse rate 已达 94.5%、eligible 达 77.7%，validity bottleneck 已经不严重。PDF 要求无 SFT 主线正是为了避免 SFT 先解决大部分合法性问题，使 RL 只能在极稀疏的质量信号上训练。

### RQ7：现在是否应该优先加入自适应算子权重？

不应该作为下一项优先工作。本轮虽显示 `m1` 的 conditional parent-win 较高，但 reward 定义、fixed bank、跨问题/规模、same-valid 诊断仍未完成。现在加入 AOS 会同时改变候选分布和算子调用比例，使奖励问题更难识别。按照 PDF 主线，自适应算子权重应保留为后续性能瓶颈机制，而不是用来掩盖尚未对齐的 reward 与评估设计。

## 19. 替代解释与威胁效度

### 19.1 内部效度

- 6 seeds 的配对设计优于非配对均值，但统计功效仍低。
- vLLM/on-policy 采样并非严格逐 token 可复现；LR0 与 B0 的差异表明工程路径不可忽略。
- 每轮重建 Trainer 的语义会重置 Trainer 内部状态，但 LoRA 权重可继续累积；如果 optimizer state 未跨轮保存，则它不是连续 500 step 的普通 GRPO 训练，而是 500 次单组更新组成的在线过程。该语义必须在论文中明确，不能简单写成“训练 500 steps”而不说明重建方式。
- 当前历史日志足以证明模型在更新，但不足以证明所有父代/候选使用完全相同的随机数流。

### 19.2 构念效度

- 最终 archive best 是搜索系统指标，同时受模型、算子、archive 和随机采样影响，不等同于模型离线能力。
- Eligible、registered、novel、parent-win、frontier 是不同构念，不能相互替代。
- 当前 `{{idea}}` 出现率太低，不能把日志称为完整“idea-level evolution trace”。
- Aggregate 不是 CALM；没有 CALM 源码或独立运行结果时，不能声称奖励与 CALM 完全一致。

### 19.3 外部效度

- 只有 TSP50；小规模问题可能很快进入性能天花板，也可能无法暴露复杂约束下的执行失败。
- 未覆盖 OBP、JSSP 及其多种规模，无法支持跨问题/跨规模通用后训练流水线的主张。
- 使用 TSP-small SFT LoRA，不能推断 base model、其他 LoRA 或其他模型上的行为。

### 19.4 统计结论效度

- n=6 导致宽置信区间。
- 多变体比较未校正。
- 候选和轮次高度相关，只能作描述性分解。
- 跨轮次实验使用过不同代码阶段，不能直接合并为独立重复。

## 21. 严格按照 PDF 的下一阶段实验顺序

### 21.1 第一优先级：固化最终 VC-PAIR 奖励

必须先实现并用日志逐项可审计：

1. 同一候选与其直接父代在完全相同的 instance batch 上配对评估。
2. 每个 instance 保存 (d_i=f(c,i)-f(p,i))，而不仅保存聚合均值。
3. 使用预先固定的 95% CI 或可信胜率规则，不允许运行后挑阈值。
4. 固定最小实际效果阈值 (delta)，区分统计上非负与实质改进。
5. `group_valid_count < 2` 时只学习分层合法性，不启用组内质量排序。
6. 对置信为正且进入 frontier 的候选提供有限 bonus。
7. 对 exact copy 与 duplicate profile 分别惩罚；避免模型通过趋近父代获得 neutral。
8. 对 invalid、parse、exec、non-finite、interface mismatch 使用有序分层奖励，而不是一个统一负值。
9. 所有 reward 分量分别落盘，保存总 reward 之外的分解项。

### 21.2 第二优先级：固定 bank 和 search-free 诊断

建立冻结的 prompt/parent bank，并至少包含：

- 不同初始质量分位的父代；
- 不同算子类型；
- 不同失败难度；
- 固定实例批次与公共随机数；
- 训练中不进入 archive 更新的独立评估 bank。

对每个 checkpoint/策略状态报告：

- Parse/Exec/Eligible；
- (E[Q\mid valid])；
- paired win rate；
- positive/neutral/negative 比例；
- duplicate/exact-copy；
- reward std；
- fixed-bank best/mean/quantile；
- 不经过进化搜索的 search-free tail。

### 21.3 第三优先级：完成 PDF 的关键对照

建议最小矩阵为：

| 轴 | 必要水平 |
|---|---|
| 初始化 | Base/no-SFT 主线；SFT 次级协议 |
| 训练 | B0；LR0；Validity；Aggregate；valid-only within-prompt shuffle；最终 VC-PAIR |
| 搜索 | 原始 EoH；repair/template 强基线 |
| 任务 | 至少 TSP 与 OBP |
| 规模 | 每任务至少一小一大，优先加入能暴露约束失败的大规模 |
| seed | pilot 2–3；正式至少 5–6 |

当前三天时间约束下，不应一开始铺满所有问题×规模×6 seeds。应先以 1–2 seeds 的短预算验证 reward 分布、positive 密度、duplicate 轨迹和日志完整性；只有通过 go/no-go 后才扩展正式矩阵。

### 21.4 第四优先级：same-valid 与效率分析

除固定 500 轮预算外，必须增加：

- best-so-far AUC；
- QueriesToKValid；
- ValidEvalsToTarget；
- 相同 eligible 数下的 best/mean quality；
- 时间、token、程序评估和显存归一化；
- 每个可靠 positive/frontier 改进的边际成本。

只有在控制 valid supply 后 VC 仍提升质量，才能支持“RL 学到了条件质量”而不是“仅产生更多可用样本”。

### 21.5 自适应算子权重的进入条件

在以下条件同时满足前，不进入 AOS：

1. 最终 VC-PAIR 已按 PDF 固化；
2. fixed bank 上出现稳定 conditional-quality 改善；
3. 至少两个问题/多个规模验证奖励不是 TSP50 特化；
4. 固定算子分析显示收益受算子分配显著限制；
5. 有离线或延迟更新的 operator credit，避免与即时 reward 共振。

这与 PDF 将算子调度放在核心奖励诊断之后的优先级一致。

## 24. 最终结论

这 36 组实验已经解决了两个工程问题：GRPO 开关和零学习率对照真实生效，完整 500 轮训练能够稳定落盘；同时也给出了一个重要的科学否定结果：当前的 Aggregate、Validity 和临时 VC 奖励都没有在 TSP50 上形成相对 B0/LR0 的可复现最终收益。

本轮最有价值的发现不是某个终点均值的微小高低，而是完整的中间机制链：RL 能显著提高解析、执行和 eligible 供给；Validity 很快因组内同奖而饱和；Shuffled 即使产生最多有效候选也不能提高质量；Aggregate 与临时 VC 则逐步增加重复、降低新颖性；临时 VC 主要把 negative 变为 neutral，而真正 positive 的父子改进极度稀疏。这组证据与 PDF 所要求的 validity-mediated diagnosis 高度一致，并明确指出下一步应修正什么。

因此，当前最严谨的阶段性判断是：

> 本项目已经完成“将真实 GRPO 训练嵌入 EoH 并建立基本消融日志”的工程阶段，但尚未完成 PDF 定义的最终奖励与验证阶段。当前结果不能证明 GRPO 提高了条件质量，也不能否定尚未按规范实现的 VC-PAIR，更不能与 CALM 直接等同或宣称超越。下一阶段应先完成最终 VC-PAIR、fixed bank、valid-only shuffle、repair baseline 和无 SFT 主线，再扩展到 OBP/JSSP 与多规模；自适应算子权重应继续后置。
